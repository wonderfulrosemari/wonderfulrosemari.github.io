LUNO

통화 음성의 언어·비언어 신호와 문자 URL을 결합해 보이스피싱 위험을 판별하는 모바일 보안 서비스

팀 개발 기간
2025.10–2026.01
팀 구성
3인 팀 · 팀장
후속 작업
대회 이후 개인 모델 개선

담당 업무 팀장으로 구조 설계·기능 통합·배포를 진행하고, 대회 이후 탐지 정확도를 높이기 위해 음성 특성을 직접 추가했습니다.

대표 결과 Google Play 배포 · 대회 이후 개인 개선으로 탐지 정확도 약 86% → 92%

OVERVIEW

프로젝트 개요

LUNO는 통화 음성과 문자 URL을 분석해 보이스피싱 위험도를 알려주는 Android 보안 서비스입니다. 대회 당시에는 STT 전사 텍스트를 중심으로 통화 위험을 분석하고 문자 URL을 공공 목록과 대조했습니다. 대회 이후에는 제가 발화 특성을 추가해 탐지 정확도를 개선했습니다.

4개 엔진의미·규칙·통계·문맥 신호를 병렬 분석

PROBLEM & SOLUTION

문제 인식과 해결

기관 사칭과 취업 사기 문구는 육안으로 구분하기 어렵고, 문자 URL은 링크를 누르기 전 위험 여부를 확인하기 어렵습니다. 초기 텍스트 모델의 탐지 정확도는 약 86%였지만, 문맥과 발화 방식에서 드러나는 위험 신호가 충분히 반영되지 않았습니다.

  • 팀장으로서 금융감독원 보이스피싱 사례 약 140건을 다시 살펴 누락된 사례의 공통점을 찾고, 텍스트 분석만으로 포착하기 어려운 위험을 개선 과제로 정리했습니다.
  • 음성 입력 → CLOVA STT 전사 → AI 분석 → 위험도 결과로 처리 단계를 나누고, 앱·백엔드·AI 서버가 각 단계의 요청과 응답을 연결하도록 구성했습니다.
  • 대회 당시 CLOVA STT 전사문을 의미·문맥·통계·패턴 관점으로 나눠 분석했습니다. 학습 데이터와 평가 데이터는 7:3으로 분리했으며, 이 단계에는 음성 특성을 반영하지 않았습니다.
  • 신고 이력이 없는 초기에도 문자 조회가 가능하도록 공공 URL 데이터를 기준 목록으로 활용했습니다. 이후 사용자 제보를 검토·축적해 조회 범위를 넓히는 방향으로 설계했습니다.

IMPLEMENTATION

구현 내용

앱에서 분석 시작

홈 화면에서 통화 음성 분석과 문자 검사를 선택합니다.

통화 음성 위험도 확인

녹음 파일과 상대 번호를 전달한 뒤 위험 점수·등급·사기 의심 여부를 보여줍니다.

문자 URL 검사

문자에 포함된 URL을 검사하고 탐지 결과를 바로 확인할 수 있습니다.

분석 요청에 필요한 정보

통화 상대 번호를 함께 입력해 녹음 파일과 번호 정보를 한 요청으로 보냅니다.

DATA FOUNDATION

문자 URL 데이터와 조회 흐름

초기 데이터 · 공공 URL 목록
서비스를 처음 시작할 때는 사용자 신고 데이터가 없었습니다. 공공데이터로 공개된 피싱·스미싱 URL 목록을 초기 조회 기준으로 삼아, 제보가 쌓이기 전에도 알려진 위험 링크를 확인할 수 있도록 했습니다.
서비스 적용 · URL 대조
백엔드는 문자에서 전달받은 URL 목록을 MySQL의 phishing_url 테이블과 대조합니다. 일치한 URL이 있으면 탐지 여부와 해당 주소를 반환합니다. 문장 전체를 분류하는 음성 AI와는 별도의 목록 기반 검사입니다.
확장 방향 · 사용자 제보 축적
공공 목록을 시작점으로 두고, 사용자 제보를 접수한 뒤 중복 제거와 관리자 검증을 거쳐 조회 데이터에 반영하는 흐름을 구상했습니다. 검증된 제보가 쌓이면서 새로운 스팸문자와 피싱 URL까지 조회 범위를 넓히는 방향입니다.

DETECTION SIGNALS

AI 탐지 신호와 점수 구성

대회 당시에는 같은 전사문을 네 가지 관점으로 분석했습니다. 아래 음성 보완 단계는 정확도를 높이기 위해 대회 이후 제가 추가한 부분입니다. 텍스트 엔진의 가중치와 후속 음성 신호를 구분해 보여줍니다.

01 · 전사 텍스트 병렬 분석

35% · MEANING

SentenceTransformer

표현이 달라도 같은 의도를 가진 문장을 의미 유사도로 찾습니다.

  • ‘계좌 번호’ ↔ ‘통장 번호’
  • 기관·자산 보호 관련 표현
  • 구어체·유사 문장
35% · PATTERN

Rule Engine

명확한 수법이 드러나는 고정 표현과 패턴을 빠르게 포착합니다.

  • 기관 사칭 키워드
  • 송금·계좌 이동 유도
  • 악성 URL·앱 설치 패턴
15% · STATISTICS

Naive Bayes

과거 피싱 문장 패턴을 바탕으로 통계적 사기 확률을 계산합니다.

  • 단어·표현의 확률
  • 짧은 문장 기준선
  • 딥러닝 오판 보완
15% · CONTEXT

DistilBERT

문장 전체의 위협·압박 맥락을 파악하면서 추론 속도를 고려합니다.

  • 문맥 위험도
  • 재촉·압박 톤
  • 문장 전체의 부정적 뉘앙스
02 · 대회 이후 추가

발화 특성

대회 이후에는 전사문만으로 놓칠 수 있는 발화 특성을 보완했습니다. 아래 특성은 텍스트 엔진의 가중치와 구분해 확인합니다.

  • 발화 속도
  • 무음 구간
  • 연속 발화 시간 · 몰아붙이는 발화
03 · 결과 제공

가중 점수와 등급

대회 당시에는 4개 텍스트 엔진 점수를 가중 합산했습니다. 이후 개선에서는 음성 특성을 보완 신호로 함께 고려했습니다.

  • 안전 0–30
  • 주의 31–60
  • 위험 61–100
  • 점수 · 사기 유형 · 요약 근거

ARCHITECTURE

아키텍처

  • Android 앱이 분석 요청과 결과 조회를 담당하고, Spring Boot가 인증·분석 이력·API를 처리합니다.
  • 음성 파일은 Firebase Storage에 저장한 뒤 CLOVA STT 전사와 FastAPI 추론을 거쳐 결과를 반환합니다. Spring Boot는 사용자·인증·분석 이력을 관리합니다.
  • 문자 URL은 DB에 저장한 공공 URL 목록과 대조하고, 신고·분석 정보는 MySQL에 저장하며 Redis는 빈번한 조회와 토큰 처리에 사용합니다.
  • 분석 요청의 지연·오류와 STT·AI 의존성 상태는 Prometheus 메트릭과 구조화 로그로 수집하고, Grafana에서 운영 상태를 확인할 수 있게 구성했습니다.

RESULTS

성과

  • 팀장으로서 기획·구조 설계·기능 통합을 진행해 LUNO를 Google Play에 정식 배포했습니다.
  • 통화 음성 분석과 문자 URL 검사를 하나의 모바일 서비스 흐름으로 완성했습니다.

AFTER THE COMPETITION

대회 이후 개선

대회 당시에는 음성 특성을 반영하지 못했습니다. 대회가 끝난 뒤에도 정확도를 더 높이고 싶어 발화 속도·무음 구간·연속 발화 시간 같은 특성을 직접 추가했습니다. 데이터는 학습 70%·평가 30%로 분리해 학습에 사용하지 않은 데이터로 평가했으며, 텍스트 중심 모델의 약 86%에서 음성 특성을 보완한 모델의 92%로 개선했습니다. 이 수치는 대회 이후 개인적으로 보완한 결과입니다.

NEXT STEPS

프로젝트 보완점과 개선 방향

  • 공공 URL 목록에서 시작한 문자 조회에 제보 접수·중복 제거·관리자 검증 흐름을 더해, 이용자 제보가 쌓일수록 최신 스팸문자·피싱 URL을 확인할 수 있도록 확장할 수 있습니다.
  • 위험 판정의 근거와 신뢰도를 함께 보여주고, 공공 URL 목록과 검증된 사용자 제보의 갱신 주기를 자동화할 수 있습니다.

RETROSPECTIVE

배운 점과 회고

음성, 문자, URL 데이터처럼 성격이 다른 입력을 하나의 사용자 경험으로 연결하면서, 기능의 경계와 데이터 흐름을 먼저 설계하는 중요성을 배웠습니다.

AI 분석 결과는 단순히 점수만 보여주기보다 사용자가 이해할 수 있는 근거와 다음 행동까지 안내해야 서비스 신뢰로 이어진다는 점을 확인했습니다.
